# Feature Specifications

Use a feature spec when a change is substantial enough that observable behavior and acceptance criteria should survive beyond one chat.

Do not create specs for every tiny bug fix.

Start from `FEATURE_TEMPLATE.md`.

Suggested filename:

`YYYY-MM-short-feature-name.md`

Specs describe required behavior. Architecture details belong in `ARCHITECTURE.md` or an ADR when they are durable decisions.
